# 数据库设计

数据库共 14 张表，生产环境使用 MySQL 8.0，演示环境使用 H2 2.x（MySQL 兼容模式）。
建表脚本见 `db/schema-mysql.sql`，演示数据见 `db/data-mysql.sql`。

## 表清单

| # | 表名 | 说明 |
|---|---|---|
| 1 | sys_user | 系统用户 |
| 2 | sys_role | 角色 |
| 3 | sys_user_role | 用户角色关联 |
| 4 | project | 测试项目 |
| 5 | test_point | 测试点 |
| 6 | test_case | 测试用例 |
| 7 | test_plan | 测试计划 |
| 8 | plan_case | 计划与用例关联 |
| 9 | test_execution | 执行记录 |
| 10 | defect | 缺陷 |
| 11 | api_info | 接口定义 |
| 12 | api_script | 接口脚本 |
| 13 | env_info | 测试环境 |
| 14 | api_run_log | 脚本执行日志 |

## 核心链路

```
project ─┬─< test_point ─< test_case
         ├─< test_plan ─< plan_case >─ test_case
         ├─< test_execution >─ test_plan / test_case
         ├─< defect >─ test_case / test_execution
         ├─< api_info ─< api_script ─< api_run_log
         └─< env_info
```

## 设计约定

1. **主键**：统一 `BIGINT AUTO_INCREMENT`；
2. **逻辑删除**：所有业务表含 `deleted TINYINT`，MyBatis-Plus 全局配置为逻辑删除，删除只置位不物理移除；
3. **审计字段**：`created_at`、`updated_at` 由 `MetaObjectHandler` 自动填充；
4. **枚举存储**：状态、优先级等使用大写英文编码（如 `HIGH` / `READY` / `FIXED`），前端负责中文展示，便于扩展与国际化；
5. **JSON 片段**：用例步骤、脚本请求/断言/提取配置以 TEXT 存储 JSON，读写由服务层统一序列化；
6. **索引**：外键字段与高频查询字段建立普通索引，如 `idx_test_case_project`、`idx_execution_plan`。

## 字段字典（核心五表）

### test_point 测试点

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| project_id | bigint | 所属项目 |
| module | varchar(50) | 模块名 |
| point_no | varchar(40) | 编号，形如 TP-1-001 |
| title | varchar(200) | 测试点标题 |
| description | varchar(1000) | 设计说明 |
| priority / risk_level | varchar(10) | 优先级 / 风险等级 |
| status | varchar(20) | DRAFT / READY / OBSOLETE |
| source_type | varchar(20) | REQUIREMENT / SECURITY / PERFORMANCE / INCIDENT |
| creator_id / creator_name | bigint / varchar(50) | 创建人 |

### test_case 测试用例

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| project_id / test_point_id | bigint | 所属项目 / 关联测试点 |
| case_no | varchar(40) | 编号，形如 TC-1-001 |
| title | varchar(200) | 用例标题 |
| precondition | varchar(1000) | 前置条件 |
| steps | text | 步骤 JSON 数组 |
| expected_result | text | 预期结果 |
| priority | varchar(10) | 优先级 |
| case_type | varchar(20) | FUNCTION / INTERFACE / PERFORMANCE / SECURITY / UI |
| design_method | varchar(20) | EQUIVALENCE / BOUNDARY / SCENARIO / ERROR_GUESS |
| status | varchar(20) | DRAFT / READY / OBSOLETE |
| auto_flag | tinyint | 是否已被接口脚本覆盖 |

### test_plan / plan_case / test_execution

- `test_plan`：项目、名称、起止日期、状态（PLANNING / RUNNING / FINISHED）、负责人；
- `plan_case`：计划与用例的多对多关联，含指派人、排序号；
- `test_execution`：每次执行一条记录，含结果（PASS / FAIL / BLOCK / SKIP）、实际现象、耗时、执行人与时间。

### api_script 接口脚本

| 字段 | 类型 | 说明 |
|---|---|---|
| request_config | text | 请求配置 JSON：method、path、headers、body |
| assertions | text | 断言数组 JSON |
| extractors | text | 变量提取数组 JSON |
| env_id | bigint | 默认执行环境 |
| last_run_status / last_run_at | varchar(20) / datetime | 最近执行状态与时间 |
